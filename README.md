# LFI_tester

**Local/Remote File Inclusion** vulnerability scanner in pure Python (no third-party dependency), with automatic crawling, WAF bypass and report generation.

> Testing tool for authorized security audits (pentest, CTF, personal lab). Never use it against a target without explicit authorization.

## Features

- **Zero external dependency**: only Python 3.8+'s standard library (`urllib`, `html.parser`, `concurrent.futures`, `http.cookiejar`, `json`). No `pip install` required.
- **Automatic crawling**: discovers the site's forms and internal links (bounded depth, same origin) to widen the tested surface beyond the single page provided.
- **~370 payloads** per injection point (full arsenal by default), generated by combining traversal prefixes (multiple depths, single/double/triple URL encoding, overlong Unicode `%c0%af`, non-recursive filter bypass `....//`, Windows separators, Tomcat bypass `..;/`) with an extended target list (multi-distro system files, Apache/nginx/PHP/MySQL configs, logs for poisoning, sessions, `.env`/`.git`/`.svn`, PHP wrappers `php://filter`/`expect://`/`data://`/`zip://`/`phar://`, Windows targets, `WEB-INF/web.xml`, etc.). A `--quick` mode (20 hand-picked payloads) allows a fast triage pass.
- **WAF block detection** (403/406/429/501 codes + response signatures) and **automatic bypass**: on a block, the payload is resent with variants (URL encoding, Tomcat-style `..;/`, alternating case, null-byte suffix) until one gets through.
- **Concurrent scanning** (configurable thread pool) with network retries and optional jitter to stay discreet. Fails fast (no backoff retry) on a clearly unreachable target rather than insisting needlessly.
- **Self-contained** JSON and HTML **reports** (no external dependency) summarizing every payload tested, its status, and the bypass used if any.
- Tests both **existing URL parameters**, a **list of common parameter names** (`page`, `file`, `path`, …) on URLs with no parameters, and **each form field** individually (other fields keep their default value, instead of overwriting every field with the same payload).

### Full arsenal vs. quick mode

The full arsenal (default) is built for a thorough audit: every target/WAF has its own blind spots, so more variety = better odds of getting through. On a remote target with network latency, a full scan with crawling + parameter guessing can take a while (tens of minutes depending on the discovered surface) — increase `--workers`, reduce `--max-pages`, or target known parameters directly with `--no-crawl --no-guess-params` to speed things up. For a quick recon pass across many targets, use `-q/--quick` (reduced, high-success-probability arsenal).

## Usage

```bash
python3 LFI_tester.py -u http://target.example/ [options]
```

### Main options

| Option | Description |
|---|---|
| `-u, --url` | Target URL (required) |
| `-t, --timeout` | Timeout per request (default: 10s) |
| `-w, --workers` | Concurrent threads (default: 8) |
| `--delay` | Random delay (0..delay s) between requests |
| `--max-pages` | Max pages crawled (default: 20) |
| `--no-crawl` | Only tests the given URL, no crawling |
| `--no-forms` | Disables form testing |
| `-q, --quick` | Reduced arsenal (~20 payloads) for a fast triage pass |
| `--no-guess-params` | Disables testing of common parameter names |
| `--no-bypass` | Disables WAF bypass attempts |
| `--cookie` | Raw `Cookie` header |
| `-H, --header` | Additional header `"Name: value"` (repeatable) |
| `--proxy` | HTTP(S) proxy, e.g. `http://127.0.0.1:8080` (Burp/ZAP) |
| `-o, --output` | JSON report |
| `--html-report` | HTML report |
| `-y, --yes` | Skips the scope confirmation |
| `-v, --verbose` | Shows every test, not just positive results |

### Example

```bash
python3 LFI_tester.py -u http://127.0.0.1:8000/ --html-report report.html -y
```

## Security and ethics

On launch, the tool asks for explicit confirmation if the target isn't `localhost`/`127.0.0.1`, as a reminder that tests must be authorized. `-y` skips this confirmation in an automated environment (CI, local lab, etc.).

## Known limitations

- PHP wrappers (`php://filter`, `expect://`) only work against an actually vulnerable PHP target; they're included for coverage but guarantee nothing against a different stack.
- WAF bypass is heuristic: it improves the odds of success but doesn't guarantee getting past every WAF (particularly commercial WAFs with advanced contextual inspection).

## Development and testing

This script was developed and validated against a deliberately vulnerable, custom-built web lab (pure Python stdlib, 4 levels of increasing protection per flaw category: no protection, naive filter, WAF with a blind spot, and a secure implementation). This lab is a separate development tool, not included in this repository.
